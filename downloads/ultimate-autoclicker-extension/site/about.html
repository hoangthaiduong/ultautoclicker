About the project

Useful automation, with honest limits.

Ultimate Autoclicker is a lightweight browser extension project built around clear controls, local data and predictable operation.

01 · Transparent

Clear control

Users choose the active page, add points, compose a workflow and explicitly start or stop it.

02 · Local-first

Data stays local

Settings and workflows are stored in the browser profile. JSON export is available for backups.

03 · Practical

Honest behavior

The product documents the limits of synthetic events, background scheduling and browser permissions.

Privacy overview

Ultimate Autoclicker does not require a user account, hosted backend, API key or external analytics service. The extension uses Chrome's local storage to keep its configuration and workflows.

It does not intentionally collect browsing history or upload page content. The extension is injected only into the active tab after the user invokes the extension action; it does not request broad access to every website. The tabs API is used to message the selected tab; the manifest does not request the broad `tabs` permission.

Permissions used

  • activeTab — temporary access to the page the user explicitly activates.
  • scripting — inject the floating control into the selected page.
  • storage — save local settings, points and workflows.
  • commands — register keyboard shortcuts.

Technical limitations

Synthetic DOM events

The extension dispatches DOM-level pointer and mouse events from a content script. These events are not trusted physical input. Some websites, native browser surfaces, operating-system UI and protected flows will ignore them. Right- and middle-button events are simulated DOM events and do not open the browser's native context menu or tab behavior.

Background tabs

Click points use fixed page coordinates and require the target tab to remain visible. When the tab becomes hidden, the next coordinate action stops with an explanatory error. Chrome may also throttle or suspend background timers. This build does not implement a background-awake mode.

Service worker lifecycle

Manifest V3 service workers can be suspended and restarted. Session state is persisted where practical, but a workflow is not automatically resumed after reload, extension restart or loss of the selected page.

Page compatibility

Browser-internal pages, extension stores, protected pages, cross-origin frames and dynamic page layouts may prevent injection or make stored targets unavailable. Points are stored by tab and page URL. After reloading the same page, enable the tab again to restore its points in a stopped state. Navigating to a different URL clears that tab’s old points.
